# KBO 경기 예측 파이프라인 개선 계획

> 이 문서는 API 키가 정상적으로 제공되고, 경기·라인업·로스터·선수 시즌 및 일별 기록을 다시 수집할 수 있다는 전제에서 작성한다.

**목표:** 경기 시작 시점에 실제로 알 수 있었던 정보만 사용하여 데이터셋을 다시 만들고, 직접 승패 분류와 득점 분포 기반 모델을 공정하게 비교한 뒤 확률 품질이 가장 안정적인 모델을 운영에 배치한다.

**구조:** 데이터 수집 시점과 경기 시점을 명시적으로 분리하고, 모든 피처는 경기 시작 시각보다 과거인 기록만 사용한다. 모델 개발은 2023~2025년의 순차 검증으로 수행하고, 2026년 데이터는 모델과 확률 보정 방법을 고정한 이후 한 번만 평가한다.

**기술 구성:** Python, Pandas, NumPy, CatBoost, LightGBM, scikit-learn, SciPy, Optuna, statsmodels, pytest

## 전역 제약

- 모든 시간 비교는 `Asia/Seoul` 기준의 실제 경기 시작 시각을 사용한다.
- `s_no`는 경기 식별자로만 사용하며 날짜나 월을 추출하는 용도로 사용하지 않는다.
- 학습·튜닝·확률 보정·최종 평가 데이터는 시간 순서대로 분리한다.
- 2026년 데이터는 하이퍼파라미터 탐색과 모델 선택에 사용하지 않는다.
- 모든 모델과 데이터 분할에는 `random_state=42` 또는 `seed=42`를 고정한다.
- Pandas와 NumPy 처리는 벡터화 연산을 우선하며 `iterrows()`와 행 단위 `.apply()`를 사용하지 않는다.
- 기존 `final_training_set_v8.csv`, `best_hyperparameters.csv`, `backtest_results_2026.csv`는 비교와 감사 목적으로 보존한다.
- API 키와 비밀키를 소스 코드, 로그, CSV 및 마크다운 문서에 저장하지 않는다.
- 모델 채택 기준은 정확도보다 로그 손실, 브라이어 점수와 확률 보정 품질을 우선한다.

### 단계 5. 시점 기준 선수 피처 재설계

**대상 파일**

- 생성: `create_feature_matrix_v9.py`
- 생성: `tests/test_asof_features.py`

**구현 내용**

- [ ] 경기 키 정확 일치 방식의 `p_lookup`, `b_lookup`, `rp_mom_dict`를 제거한다.
- [ ] 선수별 기록을 경기 시작 시각순으로 정렬하고 이전 경기까지의 누적 합을 벡터화 계산한다.
- [ ] 선발 투수는 해당 경기 시작 전까지의 투구 기록만 사용한다.
- [ ] 타자는 해당 경기 시작 전까지의 타격 기록만 사용한다.
- [ ] 목표 경기의 실제 불펜 등판자 정보는 피처 생성에 사용하지 않는다.
- [ ] 불펜 후보군은 경기 시작 시점 `rosters.csv`에 등록된 선수 중 과거 투구 기록이 있는 투수로 한정한다.
- [ ] 당일 선발 투수와 경기 시작 전 누적 `GS/G >= 0.5`인 선발 역할 투수를 불펜 후보군에서 제외한다.
- [ ] 현재 시즌 등판이 3경기 미만이면 직전 시즌의 `GS/G`로 역할을 판정하고, 두 시즌 모두 표본이 없으면 역할 미확인 상태로 기록하여 불펜 성적 집계에서 제외한다.
- [ ] 불펜 후보의 성적은 목표 경기 이전 `GS=0` 등판 기록만 집계하여 다른 선발 로테이션 투수의 선발 등판 기록이 섞이지 않게 한다.
- [ ] 최근 1일·3일·10경기 불펜 투구 이닝과 투구 수를 구성하여 불펜 소모도를 표현한다.
- [ ] 현재 시즌 표본이 부족하면 직전 시즌과 리그 평균으로 축소 추정한다.
- [ ] 피처마다 `current_season`, `prior_season`, `league_prior` 중 사용 출처를 기록한다.

**축소 추정 원칙**

```text
축소 피처
= 현재 시즌 가중치 × 현재 시즌 지표
+ 직전 시즌 가중치 × 직전 시즌 지표
+ 리그 평균 가중치 × 리그 평균
```

- 현재 시즌 가중치는 타석 또는 투구 이닝이 증가할수록 단조롭게 증가한다.
- 신인과 장기 결장 선수는 리그 평균 사전분포를 사용한다.
- 5이닝 또는 10타석에서 현재 시즌 가중치가 100%가 되지 않도록 한다.
- 안정화 강도는 2023~2025년 순차 검증에서만 결정한다.

**검증 기준**

- 현재 경기의 선수 기록을 포함시키면 실패하는 회귀 테스트가 존재한다.
- 목표 경기의 실제 불펜 등판자 목록을 제거해도 피처 값이 바뀌지 않는다.
- 당일 선발과 사전 판정된 다른 선발 역할 투수가 불펜 후보군에 포함되지 않는다.
- 신규 경기 `s_no`가 과거 데이터에 없어도 피처가 일괄 기본값으로 붕괴하지 않는다.
- 피처 출처와 기준시각을 개별 경기에서 역추적할 수 있다.

**최근 10경기 대체 확률**

```text
home_rate = (홈팀 최근 10경기 승수 + 1) / (홈팀 가용 경기 수 + 2)
away_rate = (원정팀 최근 10경기 승수 + 1) / (원정팀 가용 경기 수 + 2)
fallback_home_probability = (home_rate + 1 - away_rate) / 2
```

- 두 팀 모두 목표 경기 이전의 최근 완료 경기만 사용한다.
- 시즌 초반처럼 한 팀이라도 가용 경기가 5경기 미만이면 과거 학습 구간의 리그 홈 승률을 사용한다.
- 단순 최근 승률의 과신을 막기 위해 최종 확률은 `[0.35, 0.65]` 범위로 제한한다.
- 대체 모델의 API `percent`도 항상 `fallback_home_probability × 100`으로 전송한다.
- 대체 모델의 성능은 2023~2025년 순차 백테스트에서 주 모델과 별도로 기록한다.

**검증 기준**

- 홈 승률이 0.40이고 원정팀을 선택해도 API `percent`는 40.0이다.
- 같은 사례에서 화면 표시용 선택 팀 확률은 60.0으로 API 전송값과 명확히 구분된다.
- 목표 경기 이후 결과나 더블헤더 1차전 결과를 추가해도 2차전 대체 확률이 바뀌지 않는다.
- 한 팀의 과거 경기가 5경기 미만이면 리그 홈 승률이 반환된다.
- 대체 모델 확률은 항상 0.35 이상 0.65 이하이다.
- 주 모델 성공 시 대체 모델이 호출되지 않는다.
- 대체 모델 사용 시 `model_type=fallback_recent10`과 구체적인 발동 원인이 기록된다.
- API 저장 실패 경기는 처리 완료로 표시되지 않는다.
- 동일 경기의 중복 성공 저장이 발생하지 않는다.
- 운영 예측은 경기 결과가 수집된 후에도 덮어쓰지 않는다.
