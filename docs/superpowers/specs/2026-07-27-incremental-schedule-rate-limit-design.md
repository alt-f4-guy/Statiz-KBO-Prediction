# 일정 증분 수집과 요청 제한 처리 설계

## 문제

일일 실행이 `prediction/gameSchedule`을 2023년 1월부터 현재 월까지
0.1초 간격으로 다시 호출한다. API가 HTTP 429와 `cooldown_sec`를 반환해도
클라이언트는 1초, 2초, 4초만 기다린 뒤 다음 월로 넘어가므로 쿨다운 동안
실패가 연쇄적으로 발생한다.

## 접근 비교

1. 전체 기간 재수집: 구현은 단순하지만 불필요한 호출과 429가 반복된다.
2. 현재 월만 수집: 호출은 최소지만 이전 월의 연기·미종료 경기 갱신을 놓친다.
3. 현재 월과 미종료 경기 월 수집: 일반적으로 한 번만 호출하면서 연기 경기를
   보존한다. 이 방식을 사용한다.

## 증분 월 선택

- `games_master.csv`가 없거나 비어 있으면 2023년 1월부터 현재 월까지 수집한다.
- 기존 데이터가 있으면 현재 연월을 항상 수집한다.
- 기존 데이터에서 홈 또는 원정 점수가 비어 있는 경기의 연월을 추가한다.
- 미래 연월은 요청하지 않는다.
- 선택된 연월은 중복을 제거하고 시간순으로 정렬한다.
- 응답은 기존처럼 `s_no` 기준으로 병합해 최신 행을 남긴다.

## HTTP 429 처리

- 응답 JSON의 `rate_limit.cooldown_sec`를 읽는다.
- 유효한 양수이면 해당 시간만큼 기다린 뒤 같은 요청을 재시도한다.
- 값이 없거나 잘못된 경우 기존 지수 백오프를 사용한다.
- 쿨다운은 최대 300초로 제한한다.
- 인증값이나 전체 응답 본문은 추가 로그에 남기지 않는다.

## 실패 처리

선택된 월 중 하나라도 최종 실패하면 일정 수집 단계를 실패로 종료한다.
기존 원자적 저장을 유지하므로 부분 응답으로 `games_master.csv`를 덮어쓰지
않는다. 이에 따라 `run_pipeline.py`도 다음 단계로 진행하지 않는다.

## 검증

- 기존 데이터가 완전하면 현재 월만 선택되는지 검사한다.
- 미종료 과거 월이 있으면 현재 월과 함께 선택되는지 검사한다.
- 빈 데이터에서는 2023년부터 현재 월까지 선택되는지 검사한다.
- 429 응답의 쿨다운만큼 기다린 뒤 성공 응답을 반환하는지 검사한다.
- 최종 월 실패가 수집 단계의 예외로 전달되는지 검사한다.
