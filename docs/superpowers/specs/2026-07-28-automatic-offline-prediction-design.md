# 경기 시작 후 자동 오프라인 예측 설계

## 목표

`scripts.ops.predict_2026`이 경기 시작 전에는 기존처럼 예측을 API에 제출하고,
경기 시작 후에는 자동으로 오프라인 모드로 전환해 확률을 계산하고 로컬 로그에
남긴다. 경기 후 생성한 확률은 제출하거나 전향 평가에 포함하지 않는다.

## 현재 문제

현재 실시간 예측 루프는 경기 시작 시각이 지나면 `expired` 로그만 남기고
라인업 조회, 피처 생성과 모델 추론을 모두 건너뛴다. 따라서 당일 경기가
존재해도 프로그램을 경기 시작 후 실행하면 진행 상태표에는 만료만 표시되고
예측 확률은 생성되지 않는다.

## 선택한 접근

같은 경기 처리 루프에서 현재 시각과 경기 시작 시각을 비교해 자동으로 두
모드 중 하나를 선택한다.

1. 경기 시작 전: 기존 전향 예측과 `prediction/savePrediction` 제출
2. 경기 시작 후: 오프라인 예측과 로컬 기록만 수행

별도 실행 옵션이나 별도 스크립트는 추가하지 않는다. 사용자가 실행 시각을
의식하지 않아도 되고, 기존 실행 명령과 경기 전 제출 동작을 유지하는 가장
작은 변경이기 때문이다.

## 처리 흐름

### 경기 시작 전

기존 동작을 그대로 유지한다.

1. 라인업을 조회한다.
2. 라인업 마감 전이고 라인업이 불완전하면 다음 폴링까지 기다린다.
3. 완전한 라인업과 피처 품질을 확보하면 주 모델을 사용한다.
4. 라인업 또는 피처 품질이 부족하면 최근 10경기 대체 확률을 사용한다.
5. 예측 로그를 기록하고 `prediction/savePrediction`에 제출한다.
6. 제출 성공 경기만 완료 상태로 복원한다.

### 경기 시작 후

제출 단계만 제거하고 나머지 예측 경로는 재사용한다.

1. 실제 라인업 조회를 한 번 시도한다.
2. 라인업과 피처 품질이 충분하면 주 모델을 사용한다.
3. 라인업이 불완전하거나 피처 생성·품질 검사에 실패하면 기존
   `fallback_recent10` 경로를 사용한다.
4. 경기 시작 전 생성된 미제출 예측이 있으면 같은 확률과 모델 정보를
   재사용하며 다시 추론하지 않는다.
5. 오프라인 예측 로그를 한 번 기록하고 해당 경기를 완료 처리한다.
6. `prediction/savePrediction`은 호출하지 않는다.

피처 생성은 기존 `feature_cutoff_datetime`을 그대로 사용해 현재 경기의
결과를 입력에서 차단한다. 다만 기록 시각이 경기 시작 후이므로 이 결과는
전향 성능 근거가 아닌 회고 진단용으로만 취급한다.

## 로그 계약

경기 시작 후 결과는 다음 값을 갖는 별도 기록으로 저장한다.

| 필드 | 값 |
|---|---|
| `record_type` | `offline_prediction` |
| `api_status` | `not_submitted` |
| `evaluation_role` | `retrospective_diagnostic` |
| `prediction_mode` | `offline_after_start` |

확률, 사용 모델, 대체 사유, 라인업 완성 여부, 피처 사전분포 사용률과 배포
정보는 기존 예측 로그와 동일하게 보존한다. 경기 전에 만든 예측을 재사용한
경우에도 별도 오프라인 기록을 남겨 자동 전환 완료 여부를 복원할 수 있게
한다.

기존 `expired` 기록은 삭제하거나 변경하지 않는다. 다만 `expired`는 더 이상
경기 처리 완료 조건이 아니므로 과거에 만료된 경기도 오프라인 예측을 한 번
생성할 수 있다. 다음 기록만 재시작 시 완료 경기로 복원한다.

- 성공한 `delivery`
- `offline_prediction`

동일 경기의 `offline_prediction`이 이미 있으면 다시 계산하거나 기록하지
않는다.

## 평가 격리

전향 평가기는 현재와 같이 아래 조건을 모두 만족하는 기록만 선택한다.

- `record_type == "prediction"`
- `evaluation_role == "prospective_holdout"`
- `recorded_at < game_datetime`

따라서 `offline_prediction`은 자동으로 제외된다. 이를 회귀 테스트로
고정하며, 평가 필터 자체에는 불필요한 변경을 가하지 않는다.

## 진행 상태 표시

경기 시작 전 표시는 기존과 같다.

- `모델 추론`
- `API 제출`
- `제출 완료` 또는 `제출 실패`

경기 시작 후에는 모델 추론 뒤 제출 단계를 호출하지 않고 다음 종료 상태를
표시한다.

- 진행: `6/6`
- 현재 상태: `미제출 예측 완료 · 홈 승률 <확률>`
- 제출: `미제출`

`미제출`은 실패가 아니라 의도한 오프라인 완료이므로 전체 요약의 완료 수에
포함한다.

## 오류 처리

- 일정과 라인업 API의 기존 예외 처리를 유지한다.
- 경기 시작 후 라인업 조회가 실패하면 빈 라인업으로 처리하고 대체 확률을
  계산한다.
- 경기 시작 후에는 제출 재시도 함수에 진입하지 않는다.
- 기존 경기 전 예측·제출 실패 처리와 폴링 주기는 변경하지 않는다.
- 진행 화면 오류가 예측이나 기록을 막지 않는 기존 격리를 유지한다.

## 테스트

다음 동작을 자동 테스트로 고정한다.

1. 경기 시작 후에도 확률과 `offline_prediction` 로그가 생성된다.
2. 경기 시작 후 `prediction/savePrediction` 호출 횟수는 0이다.
3. `offline_prediction`은 전향 평가 데이터에서 제외된다.
4. 과거 `expired` 로그만 있는 경기는 오프라인 예측 대상이다.
5. 기존 `offline_prediction` 로그가 있는 경기는 중복 처리하지 않는다.
6. 경기 시작 전 예측과 제출 경로는 기존과 동일하다.
7. 진행 상태 `미제출`은 완료로 집계된다.

## 범위 제외

- 모델 확률 계산식과 피처 정의 변경
- API 엔드포인트, 페이로드와 재시도 정책 변경
- 경기 결과를 사용한 사후 분석
- 실행 옵션 또는 별도 오프라인 스크립트 추가
- 기존 로그 삭제나 변환
