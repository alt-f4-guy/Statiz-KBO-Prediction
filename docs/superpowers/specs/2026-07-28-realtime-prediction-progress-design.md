# 실시간 예측 진행 상태표 설계

## 목표

`scripts.ops.predict_2026`이 수행하는 준비, 경기별 라인업 대기, 피처 생성,
모델 추론과 API 제출 상태를 터미널에서 즉시 확인할 수 있게 한다.
화면 표시만 추가하며 확률 계산, 폴링 주기, API 페이로드와 재시도 동작은
변경하지 않는다.

## 현재 문제

상위 실행기는 실시간 예측 모듈을 시작할 때
`실시간 예측 시스템 가동 시작...`만 출력한다. 실시간 모듈 내부에서는 일정
조회 실패, 최종 제출 성공과 실패만 출력하므로 장시간 라인업을 기다릴 때
프로세스가 정상 동작 중인지 알기 어렵다.

## 선택한 접근

Rich의 갱신형 상태표를 사용한다. 누적 로그보다 현재 상태를 한눈에 보기 쉽고,
경기별 진행 막대를 여러 개 표시하는 방식보다 반복 폴링 화면이 단순하다.
프로젝트의 일정·선수 수집 모듈이 이미 Rich를 사용하므로 새로운 의존성은
추가하지 않는다.

## 준비 단계 표시

실시간 루프에 들어가기 전에 다음 준비 상태를 순서대로 표시한다.

1. 인증정보 확인
2. 모델과 메타데이터 로드
3. 운영 데이터 로드
4. 배포 정보 확인

준비 단계는 성공한 항목을 완료로 바꾼다. 예외가 발생하면 기존처럼 프로세스를
실패시키되, 마지막으로 시작한 준비 단계가 실패했음을 표시한다. 인증값,
응답 본문과 로컬 비밀 파일 내용은 출력하지 않는다.

## 경기별 상태 모델

일정을 받은 뒤 각 `s_no`에 다음 표시 정보를 유지한다.

- 경기 ID
- 원정팀과 홈팀
- 경기 시작 시각
- 진행 단계
- 현재 상태 설명
- 사용 모델
- 제출 상태
- 안전하게 축약한 오류 유형

진행 단계는 다음 순서로 고정한다.

1. 경기 확인
2. 라인업 대기
3. 피처 생성
4. 모델 추론
5. API 제출
6. 완료

상태는 뒤로 이동하지 않는다. 반복 폴링 중 라인업이 완성되지 않은 경기는
`라인업 대기`를 유지하고 다음 조회 시각을 상태 설명에 표시한다.

## 종료 상태

- 제출 성공: 단계 `6/6`, 제출 상태 `성공`
- 제출 실패: 단계 `6/6`, 제출 상태 `실패`
- 경기 시작으로 제출 불가: 단계 `6/6`, 제출 상태 `만료`
- 기존 성공 로그 복원: 제출 시도 전까지 기존 확률과 모델을 복원하고
  `API 제출` 단계에서 같은 페이로드를 재사용한다.

대체 모델을 사용하면 모델 열에 `fallback_recent10`을 표시하고 상태 설명에
기존 `fallback_reason`을 표시한다.

## 화면 구성

상단에는 준비 상태 또는 전체 경기 요약을 표시한다.

```text
오늘 경기 5 | 완료 2 | 대기 2 | 실패 1
```

하단 표는 다음 열로 구성한다.

| 열 | 내용 |
|---|---|
| 경기 | `원정팀 @ 홈팀` |
| 시작 | 서울 시간 기준 경기 시작 시각 |
| 진행 | `현재 단계/6` |
| 현재 상태 | 라인업 대기, 피처 생성, 제출 완료 등의 설명 |
| 모델 | `primary`, `fallback_recent10` 또는 `-` |
| 제출 | 대기, 성공, 실패 또는 만료 |

Rich `Live`가 동일한 표를 갱신한다. 최종 성공·실패·만료 행은 화면에 남긴다.
일정 API 자체가 실패하거나 오늘 일정이 아직 없으면 표 대신 현재 대기 사유와
다음 조회 시각을 표시한다.

## 오류 처리

화면 출력 실패가 예측과 제출을 막아서는 안 된다. 상태 갱신은 인메모리 표시
정보만 변경하며 기존 운영 로그 기록과 API 예외 처리는 유지한다.
표에는 예외 클래스와 이미 안전하게 만든 상태 설명만 표시하고 인증정보나
원문 응답은 포함하지 않는다.

## 테스트

화면과 운영 로직의 결합을 줄이기 위해 다음 동작을 순수 상태 계산 단위로
검증한다.

1. 새 경기가 `경기 확인`과 `1/6`으로 시작한다.
2. 상태 전이가 진행 단계를 뒤로 이동시키지 않는다.
3. 라인업 대기는 다음 조회 시각을 표시한다.
4. 주 모델과 대체 모델이 모델 열에 구분되어 표시된다.
5. 성공, 실패와 만료가 각각 `6/6` 종료 상태가 된다.
6. 전체 요약의 완료·대기·실패 수가 경기 상태와 일치한다.

기존 실시간 예측 테스트는 확률, 시간 게이트, 로그와 페이로드가 바뀌지
않았음을 계속 검증한다. 전체 단위 테스트와 구문 검사를 최종 검증으로
실행한다.

## 범위 제외

- 확률 계산이나 모델 선택 변경
- API 엔드포인트, 페이로드 또는 재시도 정책 변경
- 폴링 주기와 라인업 마감 시각 변경
- 파일 기반 추가 로그 또는 웹 대시보드
- 사용자 설정 가능한 색상과 화면 레이아웃
