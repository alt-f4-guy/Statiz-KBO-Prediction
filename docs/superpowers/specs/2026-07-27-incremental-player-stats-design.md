# 선수 기록 일일 증분 수집 설계

## 문제

현재 선수 기록 단계는 과거 전체 라인업·로스터의 979명을 대상으로
2023년부터 현재 시즌까지 최대 4,795회 API를 호출한다. 선수별 호출 간격이
없고 현재 시즌 성공분도 재실행할 때 다시 요청하므로 HTTP 429가 반복된다.
최종 요청 실패도 다음 선수로 넘어가 추가 제한을 유발한다.

## 접근 비교

1. 과거 전체 선수 유지: 오프라인 전체 재구축에는 필요할 수 있지만 일일
   예측에서 호출량이 지나치게 크다.
2. 현재 시즌 출전 선수와 최신 로스터 합집합: 은퇴 선수는 줄지만 과거에
   출전하고 현재 로스터에서 빠진 선수까지 포함한다.
3. 당일 경기 팀의 최신 로스터: 당일 실시간 예측에 필요한 타자·선발·불펜을
   포함하면서 호출량을 가장 작게 유지한다. 이 방식을 사용한다.

전체 과거 선수 백필은 일일 실행과 분리된 오프라인 작업으로 남긴다.

## 당일 선수 모집단

- 서울 날짜 기준 당일 `games_master.csv`의 비취소 경기에서 홈·원정 팀을
  추출한다.
- 각 팀에 대해 당일 이하 날짜 중 가장 최근 `rosters.csv` 스냅샷을 선택한다.
- 선택된 최신 로스터의 `p_no` 합집합만 수집한다.
- 당일 경기가 없으면 빈 모집단을 반환하고 선수 API를 호출하지 않는다.
- 당일 경기 팀의 로스터가 하나라도 없으면 조용히 축소하지 않고 실패한다.

## 수집 연도와 재실행

- 일일 실행은 현재 시즌과 직전 시즌만 사용한다.
- 종료 시즌의 정상 성공 스냅샷은 계속 재사용한다.
- 현재 시즌은 서울 날짜 기준 오늘 성공한 스냅샷이 있으면 재사용한다.
- 현재 시즌의 가장 최근 성공이 이전 날짜라면 한 번 갱신한다.
- `playerSeason`은 필요한 연도가 하나 이상일 때 선수당 한 번 호출하고,
  응답에서 필요한 두 연도만 저장한다.
- `playerDay`는 필요한 선수-연도만 호출한다.

## 요청 간격과 실패

- 모든 선수 API 호출 뒤 0.3초 간격을 둔다.
- 공통 API 클라이언트의 429 서버 쿨다운 재시도는 그대로 사용한다.
- 재시도 후에도 `StatizAPIError`가 발생하면 즉시 상위로 전달한다.
- 성공한 스냅샷은 호출 직후 추가 저장하므로 중단 후 같은 날 재실행하면
  성공분부터 이어서 처리한다.
- 최종 실패가 있으면 `run_pipeline.py`는 다음 단계로 진행하지 않는다.

## 검증

- 당일 경기 팀의 최신 로스터 선수만 선택하는지 검사한다.
- 경기가 없거나 팀 로스터가 누락된 경우를 검사한다.
- 직전 시즌 성공과 오늘 성공한 현재 시즌이 재사용되는지 검사한다.
- 어제 성공한 현재 시즌은 다시 요청되는지 검사한다.
- 호출 사이에 0.3초 간격이 적용되는지 검사한다.
- 첫 API 최종 실패가 다음 선수 호출 전에 즉시 전달되는지 검사한다.
