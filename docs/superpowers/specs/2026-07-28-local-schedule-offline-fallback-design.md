# 일정 API 제한 시 로컬 오프라인 예측 대체 설계

## 목표

`prediction/gameSchedule`이 요청 제한 또는 네트워크 오류로 실패해도 이미
시작한 오늘 경기는 로컬 `games_master.csv`를 이용해 즉시 오프라인 예측한다.
경기 전 API 제출의 안전 기준과 기존 제출 재시도 정책은 유지한다.

## 근본 원인

실시간 예측 모듈은 경기 처리 루프보다 먼저 월간 일정 API를 호출한다. 현재
API 클라이언트는 HTTP 429 응답의 서버 쿨다운을 최대 300초까지 기다리고
세 번 재시도한다. 이 내부 대기가 끝나기 전에는 진행 화면이 일정 실패 상태를
받지 못하며, 경기별 라인업·피처·모델 단계에도 진입하지 못한다.

경기 시작 후 자동 오프라인 전환은 일정 API가 오늘 경기 목록을 반환한 뒤에만
작동하므로, 일정 조회 제한 자체를 우회하지 못한다.

## 선택한 접근

예측 모듈에서 사용하는 `StatizAPI` 인스턴스만 `max_retries=0`으로 생성한다.
일정과 라인업 읽기는 한 번만 시도하며, 실패 처리는 기존 실시간 루프가
담당한다.

일정 조회가 실패하면 메모리에 이미 로드한 `games_master.csv`에서 다음 조건을
모두 만족하는 행을 선택한다.

- 서울 날짜가 오늘인 경기
- 시간대가 포함된 경기 시작 시각을 만들 수 있는 경기
- 현재 시각이 경기 시작 시각 이상인 경기

선택한 행만 기존 경기 처리 루프에 전달한다. 모두 경기 시작 후이므로 기존
시간 게이트가 자동으로 `offline_prediction` 경로를 선택하고
`prediction/savePrediction`을 호출하지 않는다.

## 대안과 제외 이유

### 429 대기 상태만 표시

현재 위치를 알 수는 있지만 최대 300초 내부 대기와 일정 의존성은 그대로라서
오늘 예측 확률을 생성하지 못하는 문제를 해결하지 않는다.

### 전역 API 재시도 정책 변경

수집기와 검증 도구까지 영향을 받아 변경 범위가 커진다. 예측 루프는 이미
60초 폴링을 수행하므로 예측 모듈 인스턴스에만 내부 재시도를 끄는 것이 더
작고 명확하다.

## 데이터 흐름

### 일정 API 성공

1. API가 반환한 오늘 경기 목록을 사용한다.
2. 경기 시작 전이면 기존 라인업 대기와 API 제출 경로를 유지한다.
3. 경기 시작 후이면 기존 오프라인 예측 경로를 사용한다.

### 일정 API 실패

1. 로컬 원천 경기 데이터에서 이미 시작한 오늘 경기만 벡터 연산으로 선택한다.
2. 대상이 있으면 진행 화면에
   `일정 API 제한 · 로컬 일정으로 오프라인 예측`을 표시한다.
3. 각 경기는 라인업 API를 한 번만 시도한다.
4. 라인업 조회가 실패하면 기존 `fallback_recent10`을 사용한다.
5. 예측 결과를 `offline_prediction`으로 기록하고 제출하지 않는다.
6. 대상이 없으면 기존처럼 다음 일정 조회 시각을 표시하고 60초 후 다시
   시도한다.

`DataFrame.iterrows()`와 `.apply()`는 사용하지 않는다. 날짜와 시작 시각
필터는 pandas 벡터 연산으로 구현하고, 최종 선택 행만
`to_dict(orient="records")`로 변환한다.

## 제출 안전성

- 로컬 일정 대체는 이미 시작한 경기만 반환한다.
- `_complete_prediction`은 제출 직전에 현재 시각을 다시 검사한다.
- 두 경계 중 하나라도 경기 시작 이후이면 제출 API를 호출하지 않는다.
- 경기 전 로컬 일정만으로는 예측을 제출하지 않는다.
- `send_prediction_with_retry`의 최대 세 번 제출 재시도는 변경하지 않는다.
- 전역 `StatizAPI` 기본 재시도 값과 다른 수집 모듈은 변경하지 않는다.

## 진행 상태

내부 300초 대기가 제거되므로 일정 API 실패가 즉시 상위 루프에 전달된다.
로컬 대체 대상이 있으면 상태표에 대체 사유를 표시하고 경기별 진행 단계를
갱신한다.

모든 경기 처리가 끝났을 때 문구는 제출 여부를 단정하지 않는
`오늘 경기 예측 처리 완료`로 변경한다.

## 중복과 로그

기존 완료 경기 복원 규칙을 그대로 사용한다.

- 성공한 `delivery`
- `offline_prediction`

과거 `expired`만 있는 경기는 로컬 대체 대상이며, 이미
`offline_prediction`이 있는 경기는 다시 계산하거나 기록하지 않는다.
로컬 일정 사용 여부를 위한 새 로그 필드는 추가하지 않는다. 화면 메시지와
기존 `prediction_mode=offline_after_start`만으로 운영 목적을 충족한다.

## 오류 처리

- 일정 API 실패와 로컬 대상 없음: 실패 상태와 다음 조회 시각을 표시하고
  60초 후 재시도한다.
- 일정 API 실패와 로컬 대상 있음: 로컬 경기 목록으로 즉시 진행한다.
- 로컬 경기 시각 변환 실패: 해당 행을 제외한다.
- 라인업 API 실패: 빈 라인업으로 처리해 기존 대체 확률 경로로 진행한다.
- 모델·피처·로그 기록 오류: 기존 예외 동작을 유지한다.

## 테스트

1. 로컬 일정 선택은 오늘 이미 시작한 경기만 반환한다.
2. 오늘 경기라도 시작 전이면 로컬 대체 대상에서 제외한다.
3. 날짜 또는 시작 시각이 잘못된 행은 제외한다.
4. 일정 API 실패 시 로컬 대상이 있으면 60초 대기 없이 경기 목록을 반환한다.
5. 예측 모듈의 API 인스턴스는 `max_retries=0`을 사용한다.
6. 로컬 대체 경기는 제출 API 호출 횟수가 0이다.
7. 라인업 API 실패는 `fallback_recent10` 경로로 이어진다.
8. 일정 API 성공 시 기존 경기 전 제출 경로가 유지된다.
9. 완료 문구가 `오늘 경기 예측 처리 완료`로 표시된다.
10. 전체 단위 테스트와 구문 검사가 통과한다.
11. 현재 실행 중인 구버전 프로세스를 종료한 뒤 실제 터미널에서
    `python3 run_pipeline.py`를 실행해 다음 결과를 직접 확인한다.
    - 300초 내부 대기 없이 로컬 일정 대체 메시지가 표시된다.
    - 오늘 경기별 모델과 홈 승률이 표시된다.
    - 각 경기 제출 상태가 `미제출`로 완료된다.
    - `prediction_log.csv`에 `offline_prediction`이 생성된다.
    - `prediction/savePrediction` 호출이나 성공 `delivery` 로그가 없다.

실제 실행 검증은 제한 시간을 두고 수행한다. 오프라인 예측 완료가 확인되면
후속 대량 선수 수집 단계로 넘어가기 전에 상위 파이프라인을 종료해 불필요한
API 호출을 추가하지 않는다.

## 범위 제외

- 전역 API 클라이언트 재시도 정책 변경
- 수집기와 검증 도구의 API 호출 변경
- 경기 전 로컬 일정 기반 제출
- 새로운 실행 옵션 또는 별도 스크립트
- 모델, 피처와 확률 계산식 변경
- 기존 로그 변환 또는 삭제
