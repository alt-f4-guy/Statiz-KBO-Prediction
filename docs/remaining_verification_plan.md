## 2. 전역 제약

- 모든 시각은 `Asia/Seoul` 기준으로 기록한다.
- 인증값·서명 헤더·전체 API 응답은 로그와 문서에 저장하지 않는다.
- `prediction/savePrediction.percent`는 항상 `P(Home) × 100`이다.
- 2026년 기존 경기 결과는 추가 튜닝·피처 선택·보정에 사용하지 않는다.
- 코드·모델·보정기·피처가 바뀌면 새 배포 ID와 전향적 시작일을 발급한다.
- 모델과 통계 재표본의 시드는 42로 고정한다.
- 운영 로그는 추가 전용으로 관리한다.

## 4. 읽기 API 계약

| 엔드포인트 | 실제 최소 계약 |
|---|---|
| `prediction/gameSchedule` | `s_no`, `gameDate`, `homeTeam`, `awayTeam` |
| `prediction/gameLineup` | `p_no`, `t_code`, `position`, `battingOrder` |
| `prediction/playerRoster` | 선수 항목의 `p_no` |
| `prediction/playerDay` | 숫자 경기 ID 최상위 키와 `p_no`, `gameDate`, `homeScore`, `awayScore` |
| `prediction/playerSeason` | 시즌 항목의 `year` |

2026-07-27 실제 호출에서 모두 HTTP 200, `result_cd=100`, 필수 필드 확인에 성공했다. 검증 로그는 `verification_logs/read_api_contract.json`에 있으며 인증값과 전체 응답은 포함하지 않는다.

## 5. 다음 경기의 쓰기 API 검증

실제 제출 가능한 경기에서 다음 순서로 확인한다.

1. 운영 모델·데이터·시간 분할 명세와 Git 커밋의 체크섬을 확인한다.
2. 경기 시작 전에 실시간 예측 프로세스를 시작한다.
3. `prediction` 이벤트가 API 호출 전에 한 번 기록됐는지 확인한다.
4. `P(Home)<0.5`인 경우에도 `percent`가 뒤집히지 않았는지 확인한다.
5. 성공 후 `delivery`·`success` 이벤트가 추가됐는지 확인한다.
6. 운영 화면의 선택 팀 확률이 로컬 `selected_team_probability`와 일치하는지 확인한다.
7. 실패가 발생하면 동일 `home_win_probability`로만 재시도하는지 확인한다.
8. 경기 시작 이후 신규 예측 또는 재전송이 없는지 확인한다.

| 사례 | `P(Home)` | `predictWinTeam` | API `percent` | 선택 팀 표시 확률 |
|---|---:|---|---:|---:|
| 홈 우세 | 0.60 | 홈팀 | 60.0 | 60.0 |
| 원정 우세 | 0.40 | 원정팀 | 40.0 | 60.0 |

## 6. 데이터 회귀 검사

재수집 후 다음 항목을 연도별로 비교한다.

| 지표 | 합격 기준 |
|---|---:|
| `s_no` 중복 | 0건 |
| 선수-경기 `(p_no, s_no_key)` 중복 | 0건 |
| 선수-연도 `(p_no, year)` 중복 | 0건 |
| `feature_cutoff_datetime >= game_datetime` | 0건 |
| 수치 피처 무한대 | 0건 |
| 2026년 핵심 피처 결측률 | 0% |
| 홈·원정 대응 피처 누락 | 0개 |

전체 기간에는 2023년 개막 초기 리그 사전분포 행이 존재할 수 있다. 이 행은 별도로 집계하고, 2026년 결측 0% 기준과 섞지 않는다. 리그 사전분포 사용률이 이전 데이터보다 5%포인트 이상 증가하면 모델 단계를 중단하고 수집 커버리지를 조사한다.

## 7. 전향적 평가

현재 전향적 시작일은 `2026-07-28`이다. 다음 조건을 모두 만족하는 비무승부 경기만 평가한다.

- 지정 배포 ID의 `prediction` 이벤트
- `evaluation_role=prospective_holdout`
- 시작일 이후이며 경기 시작 전에 기록된 최초 예측
- 종료 결과가 있는 경기

고정 기준선은 2023~2025년 비무승부 2,116경기의 홈 승률 `0.5184310018903592`다.

```text
손실 차이 = 모델 손실 - 기준선 손실
```

경기일 블록 부트스트랩 2,000회, 시드 42로 로그 손실과 브라이어 차이의 95% 신뢰구간을 계산한다.

| 판정 | 조건 |
|---|---|
| 추가 관찰 | 100경기 미만 또는 300경기 미만의 조기 구간 |
| 데이터 파이프라인 점검 | 월간 대체 모델 20% 초과 또는 사전분포 사용률 10%포인트 초과 증가 |
| 모델 재검토 | 300경기 이상이고 두 손실 차이 신뢰구간 하한이 모두 0보다 큼 |
| 재보정 검토 | 300경기 이상이고 보정 절편·기울기 기준 위반 |
| 유지 | 한 확률 지표가 명확히 우수하고 다른 지표가 명확히 악화되지 않음 |

판정 우선순위는 데이터 파이프라인 점검, 모델 재검토, 재보정 검토, 추가 관찰, 유지 순서다.

## 8. 최종 운영 완료 기준

다음 조건을 모두 충족하면 잔여 검증이 완료된다.

1. 첫 제출 가능한 경기에서 실제 쓰기 API 계약이 확인된다.
2. 모든 전향적 예측이 경기 시작 전에 기록된다.
3. 모델·데이터·분할 명세와 Git 커밋을 각 예측에서 역추적할 수 있다.
4. 대체 모델은 지정 조건에서만 발동하고 원인이 비어 있지 않다.
5. 최소 300개 신규 비무승부 경기에 대해 운영 판정이 생성된다.
6. 인증 정보가 저장소와 운영·검증 로그에 존재하지 않는다.
